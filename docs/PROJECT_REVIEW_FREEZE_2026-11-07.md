- إيقاف تطوير الميزات، والدمج، وحذف الملفات، وتغيير قواعد البيانات حتى صدور قرار استئناف صريح.
- هذا المستند يُثبت حالة مستودع Git فقط. **لا يُوقف عمليات خادم يعمل بالفعل**، ولا يقوم بنشر أو تغيير PM2/Nginx/Supabase/Meta.

- لا يعني نجاح الاختبارات الآلية أن كل شاشة أو عملية إرسال أو Webhook قد اختُبرت داخل متصفح بمستخدم إنتاجي.
- عند الاستئناف: افتح فرع عمل جديدًا من مرجع التجميد، ولا تبدأ بتطبيق تغييرات عشوائية على `main`.

## 3. البنية البرمجية المعتمدة

| المجال | المثبت من الملفات |
| --- | --- |
| تطبيق الويب | TanStack Start + TanStack Router؛ `src/router.tsx` و`src/routes/**` |
| واجهة الاستخدام | React + Tailwind CSS v4، هيكل RTL `src/components/azwa/app-shell.tsx` |
| الخادم | Nitro بخيار `node-server`؛ `.output/server/index.mjs` |
| إدارة الحزم | `bun@1.3.3`، ملف `bun.lock`، تثبيت `--frozen-lockfile` |
| تشغيل الإنتاج المستهدف | Node.js 24+ وPM2 باسم `azwa-app` على `127.0.0.1:8085` |
| الدخول | Supabase Auth مع التحقق من عضوية المؤسسة بالخادم |
| نطاق WhatsApp | `all / business / waba / number`؛ معرّفات UUID داخلية منفصلة عن Meta IDs |
| التحكم بالوصول | وظائف خادم مقيّدة بالمصادقة وRPC/permissions في المسارات التي تمت مراجعتها |
| التحقق من الجودة | TypeScript لنطاق المسارات ووحداتها المستوردة، ESLint، اختبار أمن، عقود التكامل، شجرة المسارات، اختبار Nitro HTTP |

**مهم:** `tsconfig.json` يفحص مداخل التشغيل والوحدات المستوردة منها تحت `strict`؛ لا يمثل فحص جميع الملفات المعزولة أو كل الكود التاريخي. وفي `package.json` ما زال رقم الحزمة `1.0.0`؛ نسخة التجميد هي **وسم مراجعة مسبق** وليست تغييرًا صامتًا لإصدار الحزمة.

## 4. الوظائف الموجودة داخل الشجرة النشطة

أقسام تنقل فعلية لها ملفات مسارات:

- الرسائل والعملاء: `/dashboard`, `/inbox`, `/contacts`, `/media`, `/files`, `/templates`, `/flows`, `/campaigns`, `/automation`.
- إدارة Meta: `/infrastructure`, `/wabas`, `/numbers`, `/meta-app`, `/webhooks`, `/credentials`.
- المراقبة: `/monitor`, `/health`, `/alerts`, `/notifications`, `/errors`, `/sync-doctor`, `/queues`, `/dead-letter`, `/api-logs`.
- الإدارة والتحليل: `/analytics`, `/reports`, `/app-review`, `/users`, `/audit`, `/settings`.

وجود رابط ومسار يعني أن الشيفرة موصولة بمسار TanStack؛ **لا يثبت أن القراءة أو الكتابة الحية نجحت في كل صفحة**.

### آخر أعمال الدمج والتحسين التي ثبت وجودها

- قائمة اختيار حسابات WhatsApp بأسماء العرض التسعة وربطها بنطاق UI، مع حفظ الاختيار والتحقق من سلامة قيم التخزين.
- اسم الحساب يعتمد خريطة الهواتف المعروفة في `src/lib/azwa-number-labels.ts`، وليس مزامنة أسماء معتمدة من Meta. يلزم تحقق دوري من التحديث عند إضافة/تعديل أرقام.
- تغيير نطاق المحادثات، جهات الاتصال، الجداول المشتركة، الملفات والوسائط في المسارات المربوطة؛ اختيار النطاق في UI ليس بديلًا عن تفويض الخادم.
- تصحيح الرد داخل المحادثة ليُحل رقم المستلم من المحادثة/قناة الاتصال بالخادم بدل استعمال UUID كرقم هاتف.
- صفحة توثيق Meta والمساعدة في `/settings`، وخيار جهة اتصال لاختبار القوالب.
- ربط صفحة `/notifications` بالتنقل والتحقق من `integrations.manage` قبل عرض أسرار روابط Webhook.
- معالجات استرداد خطأ المسار في الجذر والراوتر والمسار المحمي، وعدم تسجيل الخروج بسبب فشل خدمة مؤقت.
- اختبار تشغيل Nitro داخل CI يتأكد من مجموعة صفحات أساسية؛ **لا يغطي جميع التفاعلات ولا يثبت جودة واجهة متصفح مرئية**.

## 6. سجل المخاطر والديون التقنية (للاستئناف)

### P0 — ممنوع إعلان جاهزية الإنتاج دون إغلاقها

1. **توثيق إنتاج حي:** تسجيل دخول حقيقي، تجربة تبديل الحسابات والصفحات، صلاحيات مستخدمين مختلفين، ومراجعة حالات الفشل في المتصفح والخادم.
2. **نسب Meta وSupabase:** مطابقة رقم الإرسال، عمليات Webhook، الأسرار، صلاحيات `azwa_can_send_number`، اشتراكات WABA، وحالات الرسائل الفعلية.
3. **قاعدة البيانات:** ملفات `supabase/migrations/**` الـ72 ليست سلسلة ترحيلات قاعدة الإنتاج النظيفة. يمنع تنفيذ `supabase db push` بناءً عليها. راجع `supabase/MIGRATIONS.md` و`supabase/sql/production_preflight.sql`.
4. **متغيرات البناء:** `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` تُستهلك عبر `import.meta.env`؛ تُحقن عند **البناء**. اجتياز CI بقيم placeholder لا يغني عن بنائها بالقيم التشغيلية الصالحة في الخادم. لا تنقل مفاتيح خدمة الخادم إلى متغيرات `VITE_`.
5. **دليل النشر:** `deploy/README.md` ما زال يتضمن صياغة تفيد وجود خيار ترحيلات مباشر بينما `deploy/deploy.sh` يرفض `--apply-migrations` صراحة؛ يعتمد النص التنفيذي لسكربت النشر، ويحتاج توحيد الوثائق لاحقًا.

### P1 — ضبط قبل التوسع الوظيفي

1. مراجعة كل جداول العرض ومصادر APIs للتأكد من أن تبديل `Scope` يقيّد البيانات من جهة الخادم وليس الفلاتر المرئية فقط.
2. تدقيق جميع عمليات الكتابة والحذف وإرسال الرسائل وملفات MinIO من ناحية `organization_id` وأذونات الموارد، والاحتفاظ باختبارات سلبية.
3. إدارة قائمة أسماء الحسابات التسعة من بيانات معتمدة (بدل خريطة نصية ثابتة) عند تغيير أرقام/أسماء Meta.
4. فحص أداء الاستعلامات والصفحات ذات آلاف السجلات، ومعالجة paging والفهارس وtimeouts بعد قياسات فعلية.
5. توحيد README و`docs/ROUTE_TREE.md` لتجنب بقاء توصيف صفحات React Router التي حُذفت بالفعل؛ لا تؤثر هذه الوثائق في Build حاليًا.

### P2 — مخزون دمج مؤجل، لا يُحذف تلقائيًا

- `_isolated_legacy/pending-tanstack-merge` يحفظ 174 ملفًا من مجموعات dashboard وflows وagents وWhatsApp وautomations وAI.
- لا تدمج `next-intl` أو `@xyflow/react` أو شيفرة Next Router مباشرة داخل شجرة TanStack؛ يلزم نقل العقود وتحقق الأنواع والصلاحيات.
- `_archived_legacy` ومجموعات التاريخ تحفظ الأدلة ولا تتحول تلقائيًا إلى شيفرة إنتاج.
- المرجع التفصيلي: `docs/INTEGRATION_STAGING.md`.

## 7. سياسة التوقف والتشغيل بعد هذا الإصدار

**ممنوع خلال التجميد:** تعديل ملفات `src/**` أو الاعتماديات أو `bun.lock`، تغيير migrations، تنفيذ auto-merge أو نشر إنتاجي غير موثق، أو تنظيف مجلدات تاريخية دون خطة.

**المسموح:** مراجعة للقراءة فقط، تحميل الأرشيف، تسجيل Issues، جمع قياسات مراقبة غير تعديلية، وإعداد خطة عمل للمرحلة التالية.

**شرط إعادة فتح التطوير:**
1. تثبيت المراجعة الجديدة على SHA الإصدار (tag) وعدم الاعتماد على `develop` المتغير.
2. إنشاء فرع مثل `feature/post-freeze-<topic>` من نقطة التجميد.
3. تحديد المشكلة بالملف والسطر والخطأ المكرر وشرط القبول.
4. PR + CI + اختبارات مصادقة وصلاحيات + staging ثم التوثيق قبل الدمج.
5. تغييرات DB بإجراءات forward-only منفصلة بعد تدقيق مخطط الإنتاج.
